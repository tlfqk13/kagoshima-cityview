# ADR 007: 기본 서체 Zen Maru Gothic 자체 호스팅

날짜: 2026-09-21 · 상태: 적용

## 배경

디자인 레퍼런스 두 곳(ひらやすみ × 杉並区, 佐賀市 #連れ帰省)은 모두 둥근 고딕 Zen Maru Gothic을 핵심 서체로 쓴다. 지금까지는 오프라인(PWA) 동작과 CSP(`font-src 'self'`) 때문에 웹폰트 없이 시스템 폰트만 썼다. 그래서 윈도우·안드로이드에서는 둥근 고딕이 나오지 않았다.

## 결정

- `next/font/google`로 Zen Maru Gothic 400·500·700을 **빌드할 때 받아 같은 도메인에서 제공**한다. 런타임 CDN 요청은 없고 CSP도 그대로 둔다.
- `preload: false`로 둔다. 일본어는 unicode-range 조각(굵기별 약 120개, 합계 약 6.7MB)으로 나뉘며, 브라우저는 화면에 쓰인 글자의 조각만 받는다(일본어 랜딩 기준 39개).
- 조각 파일은 서비스워커 **precache에서 제외**한다. 첫 방문에 6.7MB를 받게 하지 않기 위해서다. 대신 `static-font-assets` 런타임 캐시(CacheFirst, 최대 400개, 1년)에 실제로 쓴 조각만 쌓는다. 한 번 본 화면은 오프라인에서도 같은 서체로 보인다.
- `--font-sans`의 첫 항목이 Zen Maru Gothic이다. 한글 글리프는 없어서 한국어는 다음 폰트(시스템 고딕)로 글자 단위 대체된다.

## 결과

- 3개 언어 모두 라틴·일본어는 Zen Maru Gothic, 한글은 시스템 고딕으로 표시된다.
- 빌드할 때 Google Fonts에 접근해야 한다(Vercel·CI 환경은 가능). 네트워크가 없는 환경에서는 빌드가 실패할 수 있다.
- 한 번도 보지 않은 화면을 오프라인에서 처음 열면 캐시에 없는 글자는 시스템 폰트로 대체된다. 정보 전달에는 영향이 없다.

## 검증 (2026-09-21)

- 개발 서버: 외부 폰트 요청 0건, 일본어 랜딩에서 조각 39개 로드
- 프로덕션 빌드: precache의 woff2 0개(이전 366개), `sw.js` 46KB → 11KB
- 오프라인: 온라인 방문 후 조각 39개 캐시 → 네트워크 차단 후 새로고침 시 Zen Maru Gothic 40개 face 로드, 오류 0
