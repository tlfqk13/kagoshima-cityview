# 호텔 파일럿 설계서 (v1, 2026-09-23)

> 목적: 관광과에 가져갈 **첫 번째 실사용 숫자**를 만든다. 기간 4주, 호텔 3곳, 비용 약 3,000엔(카드 스탠드 3개 + 인쇄).
> 성공·실패 기준을 먼저 정해 두고, 결과가 나쁘면 나쁜 대로 배운 것을 적는다.

## 1. 가설과 지표

| # | 가설 | 지표 (A: `agg_daily`) | 성공 기준 (4주) | 실패 시 배우는 것 |
|---|---|---|---|---|
| P1 | 프런트에 둔 POP을 **투숙객이 실제로 찍는다** | `hotel_mode` 세션 수 (호텔별, 진입경로 `hotel`) | **호텔당 주 5세션 이상** (= 하루 약 1명) | 종이 QR은 안 찍힌다 → 프런트 직원이 건네는 방식(H3)으로 전환, 또는 객실 카드 |
| P2 | 찍은 사람은 **정류장 정보까지 본다** (스캔이 "실수"가 아님) | `hotel_mode` 세션 중 `stop_view`·`faq_click`·`open_maps`가 1회 이상인 비율 | **60% 이상** | 첫 화면에서 이탈 → 호텔 모드 첫 화면 재설계 |
| P3 | 「帰りに降りる」 정보가 **쓰인다** (구글맵이 못 하는 가치) | `faq_click` v=`back` 수, 호텔 모드 배너의 帰り 정류장 선택 수 | 호텔 모드 세션의 **20% 이상** | 돌아오는 길 문제는 우리가 생각만큼 크지 않음 → 제안서 강조점 조정 |
| P4 | 프런트 직원이 **도우미를 쓴다** (키 설정 시에만) | `desk_ask` 수 | 호텔당 주 3건 이상 | 직원은 안 씀 → 도우미 제거, 인쇄물에 집중 |
| 부가 | 언어 구성·시간대·헤맴 지표(`locate` 거리 구간) | — | 기준 없음, 관광과 리포트용 관찰 | — |

세션 수는 날짜별 해시로 센다(같은 사람이 3일 오면 3세션). 숫자가 작아도 부풀리지 않는다.

## 2. 대상과 기간
- 호텔 3곳: 인터뷰(`hotel-interview-guide.md`)에서 파일럿 참여 "예"인 곳. 유형이 다르면 좋다(체인/독립/게스트하우스).
- 기간: **4주** (10월 중 시작 목표). 2주는 너무 짧고(주말 2번뿐), 8주는 관광과 제안이 늦어진다.
- 대조군: 같은 기간 사이트 전체의 `direct` 진입 세션 — POP 효과를 "전체 대비 호텔 유입 비율"로 보여준다.

## 3. 절차

| 주차 | 할 일 | 담당 | 산출물 |
|---|---|---|---|
| 0주 (준비) | 인터뷰 3곳 → 참여 호텔 확정 → 호텔별 A6 POP 인쇄(`/card/site?hotel=slug`, QR은 `?hotel=`로 진입 태그됨) + A4 포스터(원하는 곳만) + 카드 스탠드 3개(100엔숍) → 전달 | 사장님 | 기록 시트 3장, 사진(설치 모습) |
| 0주 | `hotels.json`의 참여 호텔 slug 확인, 호텔별 리포트 쿼리 준비 | Claude | `scripts/report`(월간 리포트 생성기 초안) |
| 1주 말 | 호텔에 짧은 안부 연락(문제 없나, 위치 그대로인가). 첫 주 숫자 확인 — **0이면 위치 문제인지 QR 문제인지 즉시 점검**(직접 가서 찍어 본다) | 사장님 / Claude | 1주차 메모 |
| 2주 말 | 중간 집계. P1이 0에 가까우면 남은 2주는 "직원이 건네는 방식"으로 바꿔 시험 | Claude → 사장님 | 중간 수치 1장 |
| 4주 말 | 최종 집계 → 호텔별 반 장 리포트 3장 + 관광과용 1장 | Claude | `docs/pilot/report-2026-10.md` + PDF |
| 4주+1 | 호텔 3곳에 리포트 전달·계속 비치 여부 확인 → 관광과·교통국 접촉 | 사장님 | 관광과 제안서 v2에 숫자 반영 |

## 4. 측정 방법 (구현 완료 항목)
- 진입 경로: 호텔 POP QR = `/map?hotel=slug`(`entry=hotel`), 정류장 POP = `?src=stop`, 포스터 = `?src=poster`. **파일럿용 POP은 이 URL이 들어간 최신 버전으로 인쇄한다**(9/23 이전 인쇄본은 태그 없음).
- 개인 식별 없음. 사이트 푸터에 고지됨. 호텔에는 "何人が読み取ったか"만 알려준다.
- 리포트 쿼리(예): 호텔별 주간 세션
  ```sql
  SELECT date_trunc('week', day) AS week, entry, count(*) AS sessions
  FROM sessions_daily WHERE entry = 'hotel' GROUP BY 1, 2 ORDER BY 1;
  SELECT k AS hotel, sum(count) AS hotel_mode_views FROM agg_daily
  WHERE name = 'hotel_mode' AND day >= '2026-10-01' GROUP BY k ORDER BY 2 DESC;
  ```

## 6. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 스캔 0 — POP이 치워짐/안 보이는 자리 | 1주차 방문 확인. 설치 사진과 비교 |
| 스캔 0 — QR 자체 문제(조명·인쇄 품질) | 전달 전 3개 폰(iOS/Android/다른 카메라 앱)으로 직접 찍어 확인 |
| 호텔이 중간에 그만둠 | 계약·의무 없음이 전제. 이유를 기록하는 것이 성과 |
| 숫자가 너무 작아 해석 불가 | 그대로 보고. "4주·3곳·n세션"은 관광과에 정직한 출발점 |
| 도우미(P4)는 키가 없어 측정 불가 | 파일럿 전 모델 결정(Gemini 3.5 Flash-Lite 권장) 또는 P4 제외 |

## 7. 결과의 쓰임
- 관광과 제안서 v2: "○○ホテル等3施設で4週間試験設置。読み取り n件、うち帰りの停留所確認 m件" 한 문장. 이 한 문장이 현재 제안서의 어떤 주장보다 강하다.
- 호텔 영업: 참여 호텔 리포트를 "다른 호텔에 보여줄 사례"로(호텔명은 허락받고).
- 제품: P2·P3 결과로 호텔 모드 첫 화면과 FAQ 순서 조정.

## 8. 하지 않을 것 (파일럿 종료까지)
- 새 기능 추가(B 운행 알림, E 하차 알림 포함). 예외: 리포트 생성기.
- 호텔 대량 메일. 인터뷰한 3곳 외 확장은 결과 뒤.
- 관광과 정식 제안서 제출.
